# FocusGuard 专注统计设计方案

> 给 FocusGuard 加上专注时长的记录与可视化：首页显示今日专注时长，新增统计窗口呈现
> 热力图（近半年）、近 7 天 / 近 8 周趋势图（柱状 / 折线可切换）与随时间筛选重算的统计卡片。
>
> 贯穿本方案的原则：**统计是锦上添花，永远不许影响锁定 / 解除主流程** —— 记录失败只写日志，
> 绝不阻塞、绝不报错打断用户。实现零外部依赖，图表全部 WPF 自绘。

## 1. 目标与非目标

**目标**

1. 首页一行显示"今日累计"专注时长，专注进行中实时增长。
2. 统计窗口：6 张可筛选重算的指标卡片、GitHub 式半年热力图、近 7 天 / 近 8 周趋势图（柱 / 线切换）。
3. 会话历史落盘（`history.json`），损坏自愈、写入失败不阻塞。

**非目标**

- 不做常驻监控、不做后台采样 —— 只在 Start / Stop 的既有路径上顺手记账。
- 不做数据导出 / 云同步 / 多设备合并。
- 不做统计口径的用户配置（口径是产品语义，写死在代码与测试里）。

## 2. 统计口径

### 2.1 什么算一次"被统计的会话"

一条记录 = **Start() 成功** 到 **Stop() 最终成功** 的一次完整专注：

| 场景 | 入账？ | 说明 |
|---|---|---|
| 正常开始 → 正常结束 | ✅ | start = `StartedAt`，end = Stop 时刻 |
| 正常结束但部分解除失败，之后**重试成功** | ✅ | 首次失败不记；重试成功时按**原 `StartedAt`** 补记整场 |
| 正常结束但部分解除失败，**就此关闭程序** | ❌ | 现有逻辑关窗前会强制 Stop，失败则不退出；真发生即视为未善终 |
| 开始失败（任何步骤失败已回滚） | ❌ | 专注没有真正开始 |
| 专注中崩溃 / 被任务管理器杀掉，下次启动检测残留并解除 | ❌ | **恢复性解除不入账** —— 残留期间机器可能根本没人用，把这段算成"专注"会严重虚高 |
| 专注中直接关机后再未打开 | ❌ | 同上，永远没有记录 |

**实现判据**：`FocusController` 增加私有标记 `_sessionFromThisInstance`（默认 `false`），仅当本实例内 `Start()` 成功后置 `true`；`Stop()` 完全成功（`UnresolvedItems` 为空且操作成功）且该标记为 `true` 且 `StartedAt != null` 时写一条记录，随后标记复位。崩溃重启的实例里该标记天然是 `false`，恢复性 Stop 自然不记账 —— 不需要额外的落盘标记位。

### 2.2 跨午夜

整场归属**开始日**（`DateOnly.FromDateTime(StartedAt)`）。23:00 → 次日 01:00 的会话 2 小时全部计入第一天，第二天从 0 开始。优点：口径单一、聚合免切分、与"会话"心智一致。

### 2.3 显示口径的两处差异（有意为之）

| 位置 | 口径 | 理由 |
|---|---|---|
| 首页"今日累计" | 已完成会话总和 **+ 进行中会话实时时长** | 用户盯着数字增长符合直觉；崩溃则回退到已完成总和（那场本就不入账） |
| 统计页全部数字 | 仅已入账会话 | 打开时快照一次，所见即历史文件内容 |

进行中会话的实时部分同样归属其**开始日**：昨天 23:00 开始、此刻今天 01:00，首页"今日累计"不含这场（它属于昨天）。罕见边界，保持与最终入账一致。

## 3. 数据模型与存储

### 3.1 文件

`%LocalAppData%\FocusGuard\history.json`（与 `state.json` 同目录），内容为 `FocusSession` 数组：

```json
[
  { "startedAt": "2026-10-25T09:12:30+08:00", "endedAt": "2026-10-25T11:40:02+08:00" }
]
```

只存两个端点，时长与归属日均由端点推导，不冗余存储（避免不一致）。时区带偏移落盘（`DateTimeOffset`），跨时区夏令时也不会算错日期。

### 3.2 读写规则（对齐 state.json 的既有哲学）

- **写入**：整体序列化 → 写 `.tmp` → `File.Move(overwrite: true)` 原子替换。会话量级极小（每天几条），整体重写无性能问题。上限保护：超过 10,000 条时丢弃最旧的一半（约 27 年的量，实际到不了，纯防御）。
- **读取 / 损坏自愈**：文件不存在 → 空历史；解析失败 → 把坏文件改名为 `history.json.corrupt-<yyyyMMddHHmmss>` 保留现场、从空历史开始、写日志。**绝不抛异常阻断启动**。
- **写入失败**：`TryAppend` 返回 false + 错误信息，调用方只写日志。**绝不影响 Stop 的成败语义** —— 解除成功就是成功，丢一条统计不是用户的损失。
- **时钟回拨防御**：`Duration <= 0` 的记录按 0 时长聚合，照常保留（不删数据）。

### 3.3 Core 层 API 草案

```csharp
public sealed record FocusSession(DateTimeOffset StartedAt, DateTimeOffset EndedAt)
{
    public TimeSpan Duration => EndedAt > StartedAt ? EndedAt - StartedAt : TimeSpan.Zero;
    public DateOnly StartDay => DateOnly.FromDateTime(StartedAt.LocalDateTime);
}

public enum StatsRange { All, Last30Days, Last7Days }

public sealed class FocusHistory
{
    public static FocusHistory Load(string path);                    // 见 3.2 损坏自愈
    public bool TryAppend(FocusSession session);                     // 失败只返回 false，内部已写日志

    public IReadOnlyList<FocusSession> Sessions { get; }
    public DateOnly? FirstDay { get; }                               // 最早记录的开始日

    // 聚合（全部基于"归属开始日"）
    public TimeSpan TotalOn(DateOnly day);
    public IReadOnlyList<(DateOnly Day, TimeSpan Total)> DailyTotals(DateOnly from, DateOnly to); // 空日补零
    public IReadOnlyList<(DateOnly WeekStart, TimeSpan Total)> WeeklyTotals(int weeks, DateOnly today); // 周一为周首，含 today 所在周；锚定参数便于测试
    public int ActiveDayCount(DateOnly from, DateOnly to);           // 时长 > 0 的天数
    public int LongestStreak(DateOnly from, DateOnly to);            // 连续活跃天的最长段
    public int CurrentStreak(DateOnly today);                        // 从今天往回数；今天无记录则从昨天起算
    public DateOnly RangeStart(StatsRange range, DateOnly today);    // 7 天/30 天 = 含今天的自然日窗口
    public static int HeatLevel(TimeSpan dayTotal);                  // 0..5，见 §5.2 阈值表
    public static string FormatDuration(TimeSpan value);             // 42秒 / 36分钟 / 3小时24分 / 123小时
}
```

`FocusController` 集成：构造时 `FocusHistory.Load`；暴露 `public FocusHistory History`；Start 成功置标记、Stop 完全成功按 §2.1 记账。

## 4. 首页改动

`ElapsedText`（"已专注 HH:MM:SS"）下方新增一行 `TodayText`：

- 文案：`今日累计 3小时24分`（不足 1 分钟显示 `今日累计 42秒`；超过 100 小时显示 `今日累计 123小时`）。
- 样式与 `ElapsedText` 同款：FontSize 12，闲时 `#9CA3AF`、专注态 `#85B7EB`。
- 刷新：并入 `OnTick` / `UpdateElapsed` 既有节奏，无新增定时器。
- 可见性：**跟随现有 `ShowElapsed` 配置** —— 两者都是时长展示，尊重用户"不想看见时长"的既有选择（如需单独控制，后续再加配置项）。
- 数值：`History.TotalOn(今天) + (进行中且 StartedAt 开始日 == 今天 ? now - StartedAt : 0)`。

## 5. 统计窗口（StatsWindow）

### 5.1 窗口与总布局

- 1280×720，`WindowStyle=None + AllowsTransparency`，根 `Border` CornerRadius 16、背景 `#FAFAFA`、边框 `#E5E7EB`，`WindowStartupLocation=CenterOwner`，`ShowInTaskbar=False`，模态 `ShowDialog()`。标题栏左侧"统计"弱化标题 + ✕ 关闭，拖拽移动 —— 与设置页完全同款。
- 入口：主窗口标题栏新增图表图标按钮（Segoe Fluent Icons 字形 `&#xE9D9;`，四立柱柱状图），位于设置齿轮左侧，Tooltip"专注统计"。busy 期间与设置按钮一并禁用；专注进行中允许查看（数据是快照，不受影响）。

自上而下五个分区（垂直预算 ≈ 720px）：

| 分区 | 高度 | 内容 |
|---|---|---|
| ① 标题栏 | 40 | "统计" · 右侧 ✕ |
| ② 筛选行 | 36 | 左：`全部` `30天` `7天` 胶囊分段（默认**全部**）；右：`柱状图` `折线图` 胶囊分段（默认**柱状图**） |
| ③ 卡片区 | 约 115 | 6 张卡片，2 行 × 3 列（紧凑尺寸），白底 `#FFFFFF` 圆角 8、边框 `#E5E7EB`，卡内上为 11px `#9CA3AF` 标题、下为 17px `#374151` 数值 |
| ④ 热力图 | 170 | 近 53 周，详见 §5.2 |
| ⑤ 趋势图 | 190 | 左"近 7 天"右"近 8 周"两块，详见 §5.3 |
| ⑥ 脚注 | 24 | 趣味换算，居中，11px `#B4B2A9` |

### 5.2 热力图（自绘 HeatmapControl）

- **网格**：列 = 周（近 53 周，最右列为本周），行 = 周一（顶）…周日（底）。实现取格 13×13px、节距 17px（含间隙）→ 53 列宽 901px、7 行高 119px。左侧不设星期标注（一行七格的密度下文字标签意义不大，悬停提示已含"周几"）。
- **色阶**（6 档，当日**已完成会话**总时长）：

| 档 | 当日时长 | 颜色 |
|---|---|---|
| 0 | 0（无记录） | `#E5E7EB` 浅灰 |
| 1 | 0 < t < 2h | `#C6DDF2` |
| 2 | 2h ≤ t < 4h | `#8FBBE4` |
| 3 | 4h ≤ t < 6h | `#4D8BCB` |
| 4 | 6h ≤ t < 8h | `#185FA5` 主蓝 |
| 5 | t ≥ 8h | **彩色流光动画**（多色渐变循环流动） |

  边界值含下界：恰 2h 归第 2 档。1–4 档蓝为 `#185FA5` 的亮度梯度外推（与强调色 `#85B7EB` 同族），实现时可微调但档位语义不变。
- **流光动画（第 5 档）**：格子用线性渐变（红→黄→绿→青→蓝→紫的高饱和序列），多个 `GradientStop` 的 `ColorAnimation` 错相位循环驱动色相流动，`RepeatBehavior=Forever`，观感对齐 Claude Code ultra 档的 shimmer。**实现约束**：热力图因此采用元素化布局（`UniformGrid` + `Border`，182 个格子对 WPF 无压力）而非纯 `OnRender` —— 只有元素才能挂 `Storyboard`；动画仅挂在第 5 档格子上，窗口关闭时元素销毁、动画自然停止，不耗后台资源。
- **标注与对齐**：顶部月份标签（该月第一周所在列上方标"3月""4月"，仅月份变化的首列标）；标签槽位宽度与格子节距一致，月份与周列严格对齐；整块（月份行 + 格子）在统计页水平居中。不做图例与左侧星期标注，色阶含义由悬停提示承载。
- **悬停**：格子上方显示 ToolTip：`10月25日 · 3小时20分`；0 时长显示 `· 无专注记录`。`MouseMove` 换算所在格 → 更新 ToolTip 内容，离开网格即隐藏。
- **未来日期**：本周内尚未到来的日子画空灰格（与 0 档同色但加 40% 透明度以示区别）。

### 5.3 趋势图（自绘 TrendChartControl）

- 两块横排各约 610×190：左"近 7 天"（含今天，按天），右"近 8 周"（含本周，按周、周一为周首）。
- **一个**共用开关（②区的 `柱状图 | 折线图` 胶囊分段）同时作用于两块。
- **柱状模式**：等宽柱（柱宽 ≈ 绘图区宽 / N × 0.55，圆角顶 2px），主蓝 `#185FA5`；今天/本周柱用深蓝 `#0C447C` 高亮以示"当前"。
- **折线模式**：`StreamGeometry` 折线（笔 1.5px `#185FA5`）+ 每个数据点 4px 实心圆点；当前点用 `#0C447C`。
- **Y 轴**：以 **2h 为步长**的整小时刻度（2h / 4h / 6h / 8h / 10h …），满量程按数据向上取整；数值很大时步长加倍（超过 12h 用 4h、超过 24h 用 8h）保证刻度不超过 6 条。两张图各自独立定量程，且**周图量程下限为 14h**（2h × 7 天 —— 周汇总天然是日汇总的约 7 倍，空数据时不与日图共用 2h 基准）。网格线 `#F1F2F4` 1px，刻度标签 `2h` `4h`（11px `#9CA3AF`）。
- **X 轴**：近 7 天标 `一 二 三 …`（今天标"今天"或日期 `10/25`，避免歧义用日期+今天高亮）；近 8 周标每周周一 `9/1` `9/8` …。
- **悬停**：柱 / 点上方 ToolTip：`10/22 周三 · 2小时05分`、`10/20–10/26 · 14小时30分`。
- **空数据**（该范围全为 0）：只画基线与 X 轴标签，不画"0 高度的柱"。

### 5.4 卡片与脚注

卡片随②区筛选重算（聚合窗口 = 含今天的自然日区间；`全部` = 从 `FirstDay` 到今天，无记录时全部为 0）：

| 卡片 | 定义 |
|---|---|
| 专注总时长 | 窗口内 `Total` 之和，`36小时42分` 格式 |
| 日均专注时长 | 总时长 ÷ 窗口自然天数（7 天 ÷7、30 天 ÷30、全部 ÷ 首末日天数，均含端点），`1小时12分/天` 格式 |
| 最高单日时长 | 窗口内单日最大值 |
| 活跃天数 | 窗口内时长 > 0 的天数，`12 天` |
| 最长连续天数 | 窗口内连续活跃天的最长段，`5 天` |
| 当前连续天数 | 从今天往回数的连续活跃天数；今天尚无记录则从昨天起算（今天中途完成会话后自然续上），`3 天` |

脚注：`相当于看完 {N} 部电影`（N = 当前范围总时长 ÷ 2h 向下取整，N = 0 时显示 `还差 {M} 分钟凑满一部电影`）。纯装饰换算，永不参与统计语义。

### 5.5 空态与刷新

- 无任何记录：卡片全 0、热力图全灰、图表仅基线、脚注换行显示 `还没有专注记录，完成第一次专注后这里会亮起来`。
- 打开时快照一次，模态期间不实时刷新（正在进行的会话不入统计页，见 §2.3）；关闭再开即取最新。

### 5.6 时长补记（补记弹窗）

忘记点「开始专注」的时段，可以手动把漏记的时长补进当天：

- 入口：统计页标题栏右侧「补记时长」按钮（busy 期间统计页本就打不开，无需额外互斥；专注进行中允许补记）。
- 弹窗：无边框圆角小窗（与设置页同款风格），输入小时 + 分钟，Enter 直接种补记、Esc 关闭；打开时显示"今天已记录 X"作参照。
- 归属规则：补记会话**锚在当日零点起算**（`FocusHistory.TryBackfill(duration, now)` → `[当日 00:00, 00:00 + duration]`）——
  归属日必为当天、入账时长与输入分毫不差，也几乎不会与白天里的正常会话重叠；多次补记就是各次时长直接相加。
  已知边界：零点附近开始的正常会话可能与补记窗重叠而双重计数，属可接受的口径（补记语义是"按报的时长入账"）。
- 校验：时长 > 0 且 ≤ 24 小时（`FocusHistory.MaxBackfillDuration`）；0 / 负数 / 超限在弹窗红字提示，Core 侧再兜底一次。
- 失败语义：落盘失败（目录不可写）弹窗不关、红字提示重试，主流程不受影响（同 §3.2）。
- 成功后：统计页热力图 / 两张趋势图 / 六张卡片整体重算；首页「今日累计」由每秒刷新自然跟上。

## 6. 测试计划（tests/FocusGuard.Tests/Program.cs 新增 S 组）

沿用临时目录 + `FakeHostsBlocker` 的既有构造方式；所有文件操作用 `finally` 清理。

| 检查 | 断言要点 |
|---|---|
| S1 正常会话入账 | Start→Stop 成功后恰有一条记录，起止、时长正确 |
| S2 崩溃残留不入账（核心） | 预置 `IsFocusing=true` 的 state.json → 新实例 Stop 成功 → history 仍为空 |
| S3 失败重试后按原开始时间入账 | Stop 失败（UnresolvedItems 非空）不记账；修复后重试成功 → 一条记录且 start 为原 `StartedAt` |
| S4 开始失败不入账 | Start 回滚后 history 为空 |
| S5 跨午夜归属开始日 | 23:00→01:00 的会话：开始日 +2h，次日 0 |
| S6 损坏自愈 | 写坏 history.json → Load 不抛异常、返回空、坏文件改名保留 |
| S7 记账失败不阻塞（核心） | history 目录只读 → Stop 仍返回成功，仅日志 |
| S8 按天聚合 | DailyTotals 区间内空日补零、多会话同日累加 |
| S9 按周聚合 | 周一为周首；跨月的周归属正确；含本周共 N 条 |
| S10 连续天数 | LongestStreak 跳档断开；CurrentStreak 今天无记录回退昨天；全空为 0 |
| S11 色阶边界 | 0 / 恰 2h / 恰 4h / 恰 6h / 恰 8h / 8h+ 各归对档 |
| S12 日均分母 | 7 天 = 7、30 天 = 30、全部 = 首末自然天数（含端点） |
| S13 补记归属当天（核心） | 补记 90 分钟 → 恰一条记录、StartDay = 当天、锚在零点起算、入账时长与输入分毫不差；重读文件一致 |
| S14 多次补记累加 | 两次补记各一条记录，日总量 = 各次之和 |
| S15 非法补记拒绝 | 0 / 负数 / 超 24h 拒绝且不改动已有数据；恰 24h 放行 |
| S16 补记与正常会话并存 | 同日总时长 = 正常会话 + 补记；补记后当天计入 CurrentStreak |

UI 自绘控件不进测试套件（无 UI 测试设施），以 `dotnet build` + 人工验收覆盖；验收点见 §8。

## 9. 风险与边界

- **多实例并发**：App 无单实例互斥（现状），两个实例同时 `TryAppend` 整体重写可能互相覆盖。风险与现有 hosts 写入竞争同级，不在本方案内扩大处理。
- **统计页快照语义**：模态期间不实时刷新、进行中会话不入统计页 —— 与首页实时显示存在口径差（§2.3），文档与 UI 文案均已明示。
- **history.json 增长**：万年量级防御见 §3.2；正常使用远触不到上限。
- **自绘控件**：DPI 缩放依赖 WPF 的设备无关坐标系与既有 `UseLayoutRounding=True`，无需额外处理。
