# FocusGuard 设计方案

> Windows 11 极简专注工具：一个按钮，专注期间打不开知乎 / 虎扑 / YouTube / B 站，也启动不了 FM。
> 威胁模型：**防自己手滑，不对抗蓄意绕过**。不做常驻监控、不做篡改检测、可被任务管理器杀掉。
>
> 贯穿全局的原则：**宁可被绕过，也不能出现「限制解不干净」**。
> 当前版本 **v1.5**（四轮评审 + 复现验证后的修订版）。

---

## 0. 决策记录

| 决策点 | 选择 | 直接后果 |
|---|---|---|
| 强制力档位 | 单进程应用 | 无 Windows Service、无命名管道、无服务 DACL |
| 会话时长 | 开区间（点结束才解锁） | 无倒计时，只显示已专注时长 |
| 网络限制 | 不改任何网络设置 | 只用 hosts，无代理 / 无防火墙 / 无浏览器策略 |
| 运行中实例 | 先结束游戏进程再上锁 | 开始前弹窗确认 → 杀进程 → 上锁 |

## 1. 评审问题与修复全景

### 1.1 第四轮复审修复（v1.5）

| 问题 | 复现证据 | 修复 | 守护测试 |
|---|---|---|---|
| **同名被当成同一个文件** | 真身改名后搬到目录 A（旧位置为空），目录 B 里有另一份同名的 `fm.exe.focusguard-locked`。对 B 执行目录恢复 → 返回成功、零警告、旧记录被清空，而 A 里真正的 FM 仍处于锁定状态 | 判据从"文件名一致 + 原位置为空"收紧为「**恢复的路径与记录路径完全相同**」。路径不同就只是同名而已：**照常完成改名**，但**保留线索**，并把**原记录路径与本次恢复路径都报出来**让用户核对；确认对应后用 `--discard-record`（或界面上的"放弃该记录"）显式清除 | K1 / K2 |
| **放弃记录时忽略落盘失败** | `DiscardUnlocatedRecord` 不看 `PersistState()` 结果，仍返回成功 | 落盘失败时**还原内存记录**并返回 `false`；界面与命令行都据此报错，避免"界面说已放弃、重启后又被同一条记录挡住" | K3 |

### 1.2 复现验证发现的两个高危（v1.3 修复）

| 问题 | 复现证据 | 根因 | 修复 |
|---|---|---|---|
| **恢复线索存不下来仍继续封禁** | `Start.Success=True`、FM 已改名，但 state 文件不存在 | `PersistState()` 失败只写日志 —— 把"先可靠记录再操作"变成了口号 | `PersistState()` 返回 `bool`；<b>意图落盘失败即中止</b>，hosts 与改名一步都不做；失败时还还原内存状态，避免顺手抹掉上一次的线索。此外 `FocusState.Save` 改为**先写临时文件再替换**，中途退出不会写坏已有记录 |
| **找不到 FM 却清空恢复记录** | 把锁定文件移出记录位置、保留 hosts，再结束 → 成功、零警告、零未恢复项、原路径被清空 | `Stop()` 用**一个** `found` 同时代表 hosts 与目标文件，hosts 找到了就把 FM 缺失掩盖掉 | 两条通道**独立判定**：目标文件单独统计"记录过 / 定位到"。记录过却定位不到 → 出 Warning、**保留记录线索不清空**、界面持续显示"记录中的锁定文件未找到"，并提示 `--unlock <目录>` |

### 1.3 第三轮复审修复（v1.4）

三处问题同源：我用「在别处找不到锁定文件」反推「未定位」，但**那恰恰是"已恢复"的正常结果**；
同时新会话会无条件覆盖旧记录。修法是把「记录的目标自身状态」当作唯一判据。

| 问题 | 复现证据 | 修复 | 守护测试 |
|---|---|---|---|
| **下一次开始会覆盖尚未解决的旧记录** | 存在 `UnlocatedRecord` 时界面仍允许开始，`Start()` 直接写入当前配置路径，旧路径消失 | `Start()` 开头先检查：存在未定位记录就**拒绝开始**并说明原因；界面弹三选一对话框（再试一次恢复 / 放弃该记录并开始 / 取消）。「放弃」必须由用户显式确认，并写进日志 | J1 |
| **恢复无关文件也会清掉旧线索** | 记录指向找不到的 `old.exe`，指定目录里只有 `other.exe.focusguard-locked`，恢复后返回成功并清空了 `old.exe` 的记录 | 目录恢复只在「处理掉的文件就是记录中那一个」时才清空线索：判据是**文件名一致 + 原记录位置已无锁定文件**；否则保留线索并明确提示 | J2 |
| **已恢复的 FM 被误报为"未找到"** | 首次结束时 FM 恢复成功、hosts 失败；修好 hosts 重试成功后，FM 明明在位却仍保留"未定位"警告 | 判据从「找不到锁定文件」改为「记录的目标是否回到 `Unlocked`（原文件在位且无锁定文件）」。回到 `Unlocked` 即已恢复，出跳过项而不是警告；记录随之清空 | J3 / E9（该项原有断言已按新语义修正，原先它断言的正是这个误报） |

## 2. 架构

```
FocusGuard.exe （requireAdministrator，单实例互斥体）
   │
   ├── MainWindow            单窗口 · 单按钮 · 无边框 · 状态每秒刷新
   ├── FocusController       编排 Start / Stop / 按目录恢复，内置串行锁
   │     ├── HostsBlocker ──► C:\Windows\System32\drivers\etc\hosts
   │     ├── TargetLocker ──► fm.exe → fm.exe.focusguard-locked
   │     ├── LegacyAclCheck ─► 检测旧版本 icacls 拒绝规则残留
   │     └── AclReader       ─► 读取真实安全描述符（本地化无关）
   ├── ProcessGuard          开始前结束已在运行的 fm / Berkelium
   └── FocusState ──────────► %LOCALAPPDATA%\FocusGuard\state.json（原子写）
```

| 组件 | 位置 | 职责 |
|---|---|---|
| `FocusGuard.Core` | 类库 `net7.0` | 全部业务逻辑，不依赖 WPF，可直接测试 |
| `FocusGuard.App` | `net7.0-windows` WPF | 只有窗口与交互，不含业务规则 |
| `FocusGuard.Tests` | 控制台 `net7.0` | 无第三方依赖的测试宿主（43 项） |

## 3. 状态机与流程

`state.json` 用 `Phase` 表达阶段，用 `UnresolvedItems` 逐条表达失败项 —— 不用一个布尔值糊过去。

```
Idle ──开始──► Locking ──成功──► Locked
                  │                 │
                  └──失败──► Idle    └──结束──► Unlocking ──┬─全部确认──► Idle
                                                            └─有失败────► UnlockIncomplete
                                                                            （保留失败项，可重试）
```

### 开始专注

```
0. 若存在未定位的旧记录 → 直接拒绝并说明原因（绝不静默覆盖线索）
   界面会弹三选一：再试一次恢复 / 放弃该记录并开始 / 取消
1. 先落盘意图：Phase=Locking，记录目标路径与计划改名后的路径
   └─ 写失败 → 立即中止，hosts 与改名一步都不做（并还原内存状态）
2. HostsBlocker.Apply()   校验并生成备份 → 原子替换写入屏蔽区块
3. TargetLocker.Lock()    fm.exe → fm.exe.focusguard-locked
4. ipconfig /flushdns
5. 全部成功 → Phase=Locked（此步写失败只警告，因为线索已在第 1 步存好）
   任一步失败 → 回滚本次改动并如实报告
```

### 结束专注

```
1. Phase=Unlocking（写失败只警告，不阻塞）
2. 目标文件通道：逐个精确探测 → 还原 / 报冲突
   ├─ 记录里有、目标回到 Unlocked（原文件在位、无锁定文件）→ 视为已恢复，出跳过项
   └─ 记录里有、既无原文件也无锁定文件 → Warning + 保留记录线索（不清空）
3. hosts 通道：有我们的区块才去清（幂等）
4. 两条通道各自判定，互不掩盖
5. 全部确认还原 → 清空记录，Phase=Idle
   有尝试失败的项 → Phase=UnlockIncomplete，保持锁定，可重试
```

**关闭窗口时若解除失败 → 取消退出**，把窗口留给用户重试。

## 4. FM 拦截：改名，而不是改权限

`fm.exe` → `fm.exe.focusguard-locked`。四种状态各有明确行为：

| 状态 | 条件 | Lock | Unlock |
|---|---|---|---|
| `Unlocked` | 只有原文件 | 改名 | 无操作（幂等） |
| `Locked` | 只有锁定文件 | 无操作（幂等） | 改名还原 |
| `Conflict` | **两份都在**（游戏更新/修复工具重新生成） | **拒绝** | **拒绝** |
| `Missing` | 都不在 | 抛异常 | 无操作 |

冲突时两份文件都**不覆盖、不删除**，并输出两份完整路径让用户确认。

**为什么不用 ACL**：施加是 `/deny user:(RX)`，解除只能用 `/remove:d user` —— 后者会删掉该用户在此文件上的**全部**拒绝规则。文件原本就有拒绝规则时会被一并抹掉，等于"解锁时放宽了原有限制"。

**已知迁移代价（实测发现）**：文件上若存在旧的 `Deny(RX)`，**改名会失败**（`File.Move` 需要读属性，被 Deny 挡下）。这不是缺陷而是正确的拒绝：程序把失败原因和出口写清楚（"…存在旧的权限限制，可用 `--remove-legacy-deny` 处理"），由用户显式决定。

## 5. 网站屏蔽

在 hosts 追加标记区块，结束专注时只删这一段。四个关键细节：

1. **每个域名同时写 `0.0.0.0` 和 `::1`**。只写 IPv4 时浏览器仍会从上游 DNS 拿到真实 **AAAA 记录**并优先走 IPv6。
2. **纯字节级增删**。对 `byte[]` 做区间裁剪，区块外一字节不碰，原文件是 ANSI / GBK / UTF-8 都不受影响。
3. **保留原 ACL**。`File.Replace` 原子替换保留安全描述符与创建时间；**没有"退回覆盖写入"的兜底**。替换后回读校验内容。
4. **备份可信**。时间戳命名 + 回读逐字节校验；只备份尚未被我们改过的原始内容。

**措辞纪律**：hosts 里有区块只代表"规则已写入"，不代表浏览器访问已被阻止。

## 6. 旧版本 ACL 残留

- **检测**：`icacls /save` 导出的 DACL 是本地化无关格式（ACE 类型 `D`/`A` + 纯 ASCII SID），只统计针对当前用户 SID 的 denial ACE。
- **报告**：出现在 `--diag`、日志、界面提示行。
- **处理**：`--remove-legacy-deny` 显式移除，输出里说明它会删除该用户在这些文件上的**全部**拒绝规则、且旧版本没有保存原始 ACL。
- **绝不自动做**。

## 7. 单实例、并发与界面刷新

- **单实例**：主界面与 `--unlock` / `--remove-legacy-deny` 都先申请 `Global\FocusGuard.SingleInstance`，互斥体持有到进程退出；`--diag` 只读，允许并行。
- **操作互斥**：从 `ActionButton_Click` 进入的第一行就置 `_busy`，覆盖「弹窗确认 → 结束进程 → 锁定/解除」整段；期间按钮禁用、关闭被拦截。控制器的内部锁再把开始 / 结束 / 按目录恢复串行化。
- **有未定位记录时不覆盖**：`Start()` 会拒绝开始并说明原因，避免把旧线索静默覆盖掉。界面提供三选一
  （再试一次恢复 / 放弃该记录并开始 / 取消），「放弃」由用户显式确认并写进日志（`LastOperation`）。
- **同名不等于同一个文件**：`--unlock <目录>` 会照常还原该目录里找到的锁定文件，但只有**恢复路径与记录路径
  完全一致**时才清空记录。路径不同就保留线索并把两个路径都报出来；确认对应后用 `--discard-record` 清除。
  放弃记录若落盘失败会还原内存记录并报错，不会出现"说放弃了、重启后又冒出来"。
- **状态每秒刷新**：定时器除了更新已专注时长，还用实时探测重算底部状态行（做差值比较，避免无谓重绘）。因此游戏更新重新生成 `fm.exe` 后，冲突会在 1 秒内显示出来，不必等下一次操作。

| I. 恢复线索可靠性 | 4 | **状态写不下时开始必须中止且不施加任何限制**、**记录中的目标找不到时报警并保留线索**、状态写入采用临时文件替换、**中断时不抹掉已有记录线索** |
| J. 记录线索的归属与覆盖 | 3 | **存在未定位记录时开始被拒绝且不覆盖旧记录**、**目录恢复无关文件不清空旧线索**、**已恢复的目标重试时不误报未找到** |
| K. 同名 ≠ 同一个文件 | 3 | **跨目录同名文件不得清空旧线索（提示含原记录路径与本次恢复路径）**、**路径完全一致时才清空线索**、**放弃记录落盘失败要报错并还原内存记录** |

测试全部跑在临时目录，只有 H 组以只读方式访问真实路径。制造失败的手段是确定性的（在目标路径上放同名目录 / 在临时文件路径上放同名目录），不靠概率。

**两项验证表述的收紧**（避免过度声称）：
- D 组比较的是 **DACL**（`icacls` 完整显示输出 + `icacls /save` 导出的 DACL）与创建时间，**不是包含所有者、组、SACL 的完整安全描述符**。
- I3 只证明「正常往返后不残留临时文件」。临时文件再替换的方向正确，但**不构成异常中断或真实断电的安全证明**（见 §9 第 7 条）。

**成品与源码一致性**：`dotnet publish` 后对比 `dist/` 与 `bin/Release/` 三个二进制的 SHA256，全部一致；并用脚本检查 `dist/FocusGuard.Core.dll` / `FocusGuard.dll` 内含本轮新增文案（字符串存在性），避免"改了源码但成品是旧的"。

## 9. 已知边界（明确接受，非缺陷）

1. 浏览器开启「安全 DNS / DoH」时可绕过 hosts —— 不引代理的固有代价。
2. 开始专注前已打开的页面可能短暂仍可访问（浏览器缓存），刷新即失效。
3. 需要管理员权限，每次启动弹一次 UAC。
4. 可被任务管理器杀掉；杀掉后限制仍在，重新打开点「结束专注」或 `--unlock` 即恢复。
5. 管理员可以手工改 hosts 或把文件名改回去 —— 这是防御模型的天花板。
6. 程序自身的自动恢复**不做通配**；`--unlock <目录>` 会在用户显式指定的目录里列举 `*.focusguard-locked`。
7. **断电场景用"崩溃窗口"模拟验证，未做真实断电测试**：E8 / E9 分别覆盖"已改名未写确认""已写意图未改名"两个中断点；状态文件的"写临时文件再替换"在方向上正确，但没有证明真实断电下的数据完整性。
8. **未实测 WPF 窗口交互**（manifest 要求提权，非交互环境会卡在 UAC）。界面逻辑（互斥范围、每秒刷新、失败提示、未定位记录的三选一对话框）仅经代码审查与编译验证。
9. **权限验证的边界**：D 组比较的是 DACL，不是完整安全描述符 —— 所有者、组、SACL 不在比较范围内。
9. **运行时 .NET 7 已结束支持**：本机只有 SDK 7.0.410，故只能构建 `net7.0-windows`。本机已装 WindowsDesktop 运行时 8.0.8 与 10.0.11，装上 .NET 10 SDK（LTS）后改三处 TFM 即可迁移，代码无任何版本相关 API。

## 10. 运行方式

```bash
dotnet build FocusGuard.sln -c Release
dotnet publish src/FocusGuard.App/FocusGuard.App.csproj -c Release -o dist

./dist/FocusGuard.exe                          # 正常使用（会弹 UAC）
./dist/FocusGuard.exe --unlock                 # 解除可探测到的全部限制
./dist/FocusGuard.exe --unlock "D:\some\dir"   # 在指定目录里查找并还原被改名的文件
./dist/FocusGuard.exe --discard-record         # 确认后放弃一条未能定位的记录线索
./dist/FocusGuard.exe --remove-legacy-deny     # 显式移除旧版本留下的 icacls 拒绝规则
./dist/FocusGuard.exe --diag                   # 只读自检，输出 diag-report.txt
```

- 配置：`%LOCALAPPDATA%\FocusGuard\config.json`
- 日志：`%LOCALAPPDATA%\FocusGuard\focusguard.log`
- 状态：`%LOCALAPPDATA%\FocusGuard\state.json`
- hosts 备份：`C:\Windows\System32\drivers\etc\hosts.focusguard-<时间戳>.bak`
